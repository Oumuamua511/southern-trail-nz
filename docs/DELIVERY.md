# Southern Trail NZ 正式交付说明

## 交付基线

本版本交付一份面向实际旅途使用的“2026 新西兰南岛 13 天自驾手账”。行程日期为 2026-09-24 至 2026-10-06（D01–D13）。产品是可直接发布到 GitHub Pages 或任意静态文件服务器的单页网站，不需要构建、后端服务、账号系统或数据库。

正式站点：

<https://oumuamua511.github.io/southern-trail-nz/>

## 产品形态

页面按照出行前、行程中和现场查阅三个场景组织：

- 首屏集中呈现日期、航班、自驾天数、住宿和总里程。
- D01–D13 总览可快速跳转到任意一天。
- 南岛路线图展示 D04–D11 的路线与地标。
- 每日正文包含交通、活动、住宿、备选方案和注意事项。
- 每天的目的地面板提供 Google 地图搜索与可用时的驾车导航链接。
- 首页“灵动提醒窗”聚合下一件有时间的事项、倒计时、航班航站楼和目的地导航。
- 行前清单包含 31 项证件、航班、租车、装备和通讯准备。
- 预算可编辑人数、汇率、币种、金额、支付状态和自定义项目；贴士集中呈现费用、天气、补给、信号和驾驶安全信息。

行程数据包含 49 个地点记录，其中 7 个是等待用户本机填写的住宿占位；35 件计划事项中有 32 件已设定时间，可参与提醒倒计时。其余 3 件显示为待确认，不会伪装成准确时刻。

桌面端采用长篇旅行杂志式布局。每日正文在 900px 及以下折叠，路线图在 820px 及以下改为横向日期选择器、地图和下置详情卡。

### 路线图交互

- D03 基督城取车和 D12 皇后镇还车是静态上下文标记。
- D04–D10 显示真实公路几何，D11 显示皇后镇本地活动环。
- 悬停路线或聚焦日期会临时预览当天，但不会覆盖已锁定的日期。
- 点击或触摸日期、路线后锁定当天；再次选择当前日期、点击地图空白处或“全程路线”可复位。
- 每天显示 2–4 个来自正文的地标；图钉支持鼠标、触摸、Enter 和 Space。
- 详情卡会同步当天标题、路线、里程或活动及所选地标，并可跳转到完整日程。

## 实际实现

### 运行架构

- `index.html` 包含语义化 HTML、基础 CSS、内联 SVG 和页面骨架；目的地、提醒、现场模式、清单和预算工具位于 `assets/*.js` / `assets/*.css`。
- `assets/icons/` 包含 16 枚统一风格的透明 PNG 图标及 `style-spec.json`。
- 页面使用相对资源路径，可部署在域名根路径或 GitHub Pages 项目子路径。
- 页面没有运行时 JavaScript 依赖，也没有包安装或构建步骤；所有功能模块使用原生浏览器 API。
- Google Fonts 是唯一的视觉增强网络资源；加载失败时回退到系统字体。
- Google 地图、住宿按钮、天气和路况按钮均跳转到外部页面；本站不代理这些网络请求。
- 行前清单使用 `localStorage` 保存在当前浏览器，键名为 `southern-trail-check-*`，并提供迁移和文字备份，不会跨设备同步。
- 住宿地址和提醒时间也只保存在当前浏览器（分别使用 `southern-trail-private-place-*`、`southern-trail-event-time-*`）；不要在共享设备保存私人订单信息。
- `manifest.webmanifest` 和 `sw.js` 提供同源离线页面壳。缓存按版本清理，不缓存远程字体、地图或其他跨域资源，也不读取或同步 localStorage。

### 地图实现

- 南岛海岸线与湖泊来自 [Natural Earth 1:10m Physical Vectors](https://www.naturalearthdata.com/downloads/10m-physical-vectors/)。
- D04–D10 公路几何由开发阶段的 OSRM / OpenStreetMap 路线简化并投影到 `900 × 760` SVG 坐标系。
- D11 是皇后镇活动点的本地示意环。
- 海岸、湖泊、路线、标注和图钉均已经内联或提交到仓库。
- 生产页面不会请求地图瓦片、地理编码或路线规划 API。
- 页面保留 [© OpenStreetMap contributors](https://www.openstreetmap.org/copyright) 署名。

地图状态由 `lockedMapDay`、`previewMapDay` 和 `selectedLandmark` 驱动，统一通过 `renderMapState()` 同步按钮、SVG 路线、图钉、详情卡及 ARIA 状态。

### 目的地与 Google 地图

- `assets/trip-data.js` 为每一天维护目的地 ID、地址、Google 地图搜索词和来源说明；当前发布文件中的住宿地点故意保留为 `private-pending`，不显示已确认的私人门牌。
- 目的地精度分为 `address`、`entrance`、`place-search` 和 `private-pending`。没有唯一街道门牌的景点按名称或区域搜索，界面会提示出发前核对地图落点、停车点和实际入口。
- 页面只在用户点击 Google 地图链接后打开外部地图；本站不请求地图瓦片、地理编码或路线规划 API。Google 地图、住宿页面、天气和路况页面都需要网络。
- 用户可以在每日目的地面板填写订单中的住宿完整地址。该地址只写入当前浏览器的 `localStorage`，不会上传或自动分享；复制全程文字备份时可能包含这些私人地址。

### 灵动提醒窗与现场模式

- “灵动提醒窗”读取行程数据中的日期、时间、UTC 偏移和本地时区标签，显示下一件已安排的航班、驾驶、活动或入住事项，并按本机当前时间更新倒计时。
- 航班事项会显示航班号和航站楼（数据有记录时），并提供当天行程、目的地地址、Google 地图导航和航司官网实时动态入口。
- 没有原定时间的自驾事项不会被伪装成精确计划；用户可在提醒窗中手动设置当地出发时间，保存后才参与倒计时。修改时间只存在当前浏览器。
- 页面展示的是计划时刻，不是航班实时状态、值机截止、天气、路况或封路信息。出发前仍需查看航司、活动运营商、NZTA 和 MetService 的最新信息。

### 分享、清单与预算

- 每日分享按钮使用当天 `#day-*` 深链接；支持系统分享时调用系统面板，否则复制链接。
- 行前清单使用稳定的 `data-check-id`。新版本会从旧的顺序键迁移已勾选状态，并提供文字导出/恢复备份；数据只保存在当前浏览器。
- 预算工具使用当前 5 人规划的分类总额作为初始估算。用户可以编辑人数、NZD→CNY 估算汇率、金额、币种、已支付状态和自定义行；只有 NZD 项目按手动汇率换算。它不联网获取实时汇率，也不把分类总额当作精确报价。

### 渐进增强与无障碍

- 无 JavaScript 时仍可阅读全部日程、日期列表和完整路线网络。
- 日期控件使用原生按钮；SVG 路线与图钉具有键盘焦点、可访问名称和 `aria-pressed` 状态。
- 地标可通过 Enter 或 Space 激活，详情摘要通过 `aria-live="polite"` 更新。
- 页面提供“跳到主要内容”、清晰焦点样式和 44px 路线/图钉命中区域。
- `prefers-reduced-motion` 会移除路线抬升、透视和图钉延迟。
- `IntersectionObserver` 不可用时内容直接显示，不影响阅读。

## 维护边界

- 每日正文和静态预算参考维护在 `index.html`；目的地、计划事件和时区数据维护在 `assets/trip-data.js`，现场可编辑的预算和提醒值保存在当前浏览器。
- 更新地图日时，日期按钮、`.map-route[data-map-day]`、`.map-pin[data-map-day]` 和目标日程锚点必须同步。
- 更新日期、目的地或事件后运行 `node scripts/verify-trip-data.mjs`，确认 D01–D13、来源精度、时区偏移、清单 ID 和文章日期仍一致。
- 地图图钉只使用正文已有的景点或活动，不加入餐厅、住宿和普通补给点。
- 可见路线与透明命中路线必须使用相同几何。
- 新图标必须遵循 `assets/icons/style-spec.json`。
- 行前清单以稳定 `data-check-id` 作为新存储键；保留迁移逻辑，新增项目应使用唯一 ID，并验证文字备份可以恢复。
- 线路只用于行程总览，不替代现场导航、路况、天气或封路信息。

## 兼容与可移植性

当前发布文件不依赖本机绝对路径、运行时密钥、包安装或构建产物。其他开发者只需要 Git、现代浏览器和任一静态文件服务器即可运行页面；执行自动校验需要 Node.js 22 或更新版本。

Windows、macOS 和 Linux 的本地启动命令统一见 [README 本地预览](../README.md#本地预览)。应通过 HTTP 服务验收，避免使用 `file://`，因为浏览器对本地存储和 Service Worker 的策略不同。

GitHub Pages 使用项目子路径时，manifest 的 `scope` / `start_url` 和 Service Worker 的资源地址都以当前站点路径为基准。首次打开需要联网完成页面壳缓存；Service Worker 只能保证本站同源 HTML、CSS、JavaScript 和图标的缓存尝试。iPhone 微信是否安装、保留或恢复这些缓存取决于 WebView 和系统清理策略，当前交付没有声称已完成真实 iPhone 微信离线验证。地图、实时天气、路况、航班状态和第三方住宿页面始终需要网络，现场建议同时保留文字备份。

隐私上，当前发布文件不显示已确认的住宿门牌，但早期公开提交及 Airbnb / Booking 房源链接仍可能透露住宿位置；本次发布不改写 Git 历史。用户填写的地址、手动提醒时间、清单勾选和预算调整均留在当前浏览器；复制全程文字备份或打印会包含用户填写的地址，每日分享按钮只发送公开页面的日期链接。使用共享设备时也应注意本地浏览器数据。

## 发布验收

开发分支提交前和合并 `master` 后都应执行：

```bash
node scripts/verify-map.mjs
node scripts/verify-release.mjs
node scripts/verify-trip-data.mjs
node scripts/reminder-clock-tests.cjs
node scripts/offline-cache-tests.cjs
npx --yes html-validate@11.6.0 --rule no-inline-style:off index.html
git diff --check
```

浏览器验收覆盖：

1. 1440 × 900：日期悬停、D08 锁定、D10 临时预览、图钉选择、详情跳转和复位。
2. 320、375、390、430 CSS px：无横向溢出；灵动提醒窗展开后不遮挡首屏文字或按钮；日期条滚动、D10 锁定、图钉边界、下置详情卡和每日折叠正常。
3. 键盘：D04–D11、代表性路线和图钉均可聚焦、激活与复位。
4. 降级：减少动态效果与无 JavaScript 条件下内容仍可读。
5. 旅途工具：每天展开目的地面板，核对地图搜索、导航链接、精度提示和私人住宿地址的本机保存。
6. 灵动提醒窗：展开与收回时高度连续过渡，降低动态效果设置下立即切换；核对下一件计划事项、倒计时、航站楼/航班号、地图按钮，以及手动设置无时间自驾后的更新。
7. 清单、分享与预算：31 项清单迁移/备份恢复、当天 `#day-*` 深链接、预算编辑/支付状态/人均计算。
8. 持久化：清单、提醒时间、住宿地址和预算在刷新后保留；备份内容不应意外公开私人地址。
9. 可移植：从干净克隆目录启动服务器，确认资源和交互不依赖原开发机。
10. 线上：确认 GitHub Pages 返回成功状态、页面版本与 `master` 提交一致；真实 iPhone 微信兼容性仍需单独安排真机验收。

GitHub Actions 会在 `master`、`codex/**` 分支推送及面向 `master` 的拉取请求中执行静态校验。

## 已知边界

- 当前地图只覆盖南岛。
- 页面提供外部 Google 地图搜索/导航入口，但不提供内嵌导航、实时路况、天气、航班或预订状态。
- 清单数据只存在于当前浏览器，清除站点数据后会丢失。
- 离线时系统字体会替代 Google Fonts；已缓存的正文、本地脚本、样式和图标可继续尝试加载，缓存能否在 iPhone 微信中保留尚未验证。
- Airbnb 与 Booking 链接属于第三方内容，发布前仍需人工确认可访问性。
